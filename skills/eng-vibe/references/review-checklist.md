# 对抗审查清单(第 5 步用)

> 用独立子代理执行。审查者的任务是找茬,默认假设代码有问题。每项给出结论:通过 / 发现问题(附文件行号) / 无法验证(说明缺什么)。

## 权限与数据

- [ ] 每个数据出口(API 返回、列表接口)是否按角色脱敏?脱敏是白名单还是黑名单?(黑名单 = 问题:新字段默认泄露)
- [ ] 本次新增的字段,在所有已有出口的可见性是什么?是否被"顺手"暴露给了不该看的角色?
- [ ] 越权测试:用 A 用户的身份请求 B 用户的资源,拿到什么?
- [ ] 上传/写入路径是否带用户命名空间,服务端是否校验归属?

## 并发与幂等

- [ ] 同一操作被并发执行两次会怎样?(双抢、双扣、双发通知)
- [ ] 状态流转是否条件原子更新?还是先读后写(有竞态窗口)?
- [ ] 重放同一请求(网络重试、用户双击)是否产生重复副作用?幂等键是什么?

## 边界与失败路径

- [ ] 时区:代码运行时区和业务时区一致吗?所有涉及"当天/时段"的计算换算了吗?
- [ ] 第三方接口超时/报错时走哪个分支?该分支是设计出来的还是默认掉进去的?
- [ ] 空列表、null 字段、超长输入、非法枚举值,各是什么行为?
- [ ] 部分失败:多步操作中间挂了,数据处于什么状态?能恢复吗?

## 与宪法对照

- [ ] 逐条读 CLAUDE.md 业务红线,本次改动有没有触碰?
- [ ] 本次改动引入的新约定,有守护物吗?(没有 → 回第 2 步补)
- [ ] 常量是否引用唯一源,有没有新的裸字面量/复制粘贴的定义?

## 输出格式

审查报告 = 逐项结论列表 + 问题汇总(按严重度排序:红线违反 > 数据泄露 > 竞态 > 边界缺陷)+ 每个问题的修复建议。
